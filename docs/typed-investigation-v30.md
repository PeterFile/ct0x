# Typed investigation on public v30

This C slice composes the pinned Pi 1.4.0 typed investigation wire with the existing `MemberToolRuntime` registry and B's public v30 Store/Engine. It assumes the scoped report transport at `ee94dc367a9adc46f6c391b397191c49bb7dbb1b` and B's owner-write uncertainty fix at `25ff651bda139ad1a00eba784d4ffd873ea9f035` (#202). It adds no schema, policy, task system, lock, or authority to create a delegation. A7/v31 and multi-CLI return are not part of this slice.

## Verified postclaim composition

`MemberToolRuntimeOptions.TaskWorkReports` is a trusted composition option, off by default. It opts the registry into transport; mount the existing member-role and investigation routes on its loopback server. It cannot make a role runnable. The caller owns the claim and the capability lifetime. Nothing here is a selector exposed to the model or an extension to generic `MemberTools.Issue`.

| B wake | Postclaim profile |
| --- | --- |
| `followup` | Bind B's continuation Attempt first. `IssueFreshInvestigationOwnerTools` requires the exact live investigation role and original pending input via `GetWorkInputForMember`. Material operations come from the admitted investigation ceiling, with live B checks on every read and exact version pinning. The #196 input directory/segment, ACK, one-input handback and text-only submission codecs are reused. |
| `delegation` | Create only through the authorized owner/Engine path. `IssueWorkDelegationTools` checks the B-bound recipient, original author/Attempt and exact persisted delegation. Its transport order is optional channel read, optional Artifact-version read, then `report_work`, including the report-only case. |
| `report` | After `BindTaskWorkContinuation`, `IssueFreshInvestigationOwnerTools` requires that exact current owner Attempt and uses `GetWorkReportForMember` to read only the report selected by the wake. The report is returned unchanged; it does not select authority. The only other operations are the four #196 owner operations, individually authorized by B. The separate `IssueWorkReportRead` stays read-only. |

Postclaim discovery and issuance checks are snapshots, **not** startup authorization. Native HTTP tool handlers keep the registry read lock through the B operation so revocation drains authorized calls. B owns write replay and outcome classification. The native Pi wire derives `SHA256(operation + native call ID)`; no automatic replay is added. Typed owner tokens use the native HTTP codec only, not legacy MCP. Existing delegated report MCP transport is not a Codex typed launcher.

Independent composition: A/B may use the transport and the pinned adapter/config codec with their own trusted caller and fixture. The caller must retain the borrowed Artifact owner until token revocation completes. Production launch for these three wakes is off by default: the Pi investigation path must be enabled and configured with `--pi-fresh-investigation-work-extension`. Without that launch profile, unsupported v30 wakes remain in the normal queue while unrelated work runs. The existing plain-text followup flag, strict first-investigation route, ordinary/native Pi route, provider model selection and intake digest are unchanged by this slice.

## Final B startup contract

`CommitFreshTaskWorkLaunch` remains a plain-text followup gate and cannot authorize the three investigation roles. The owner fixtures have a real bound Attempt, exact private-CWD resource claim, and live typed getter result, yet the text gate refuses to spend the admission callback. Scoped getters or `CommitNativeSessionLaunch` are not alternatives to the typed launch gate.

`CommitInvestigationTaskWorkLaunch` makes a **single final B authorization decision in one transaction** against the existing Store model:

1. Fence the live claim with B's first conditional scope write. Verify the exact typed wake, source and target member/Turn, original Assignment/request/Task revision/Mandate/authority, current investigation policy and eligibility, and trustworthy related-Turn settlement. In the same transaction verify `starting` with no accepted, cancel, candidate or receipt evidence, the selected provider/model and no configured workspace, and the exact scheduler resource set.
2. For an owner, require the exact already-bound and currently active Attempt. Verify the original pending input for a followup, or the exact wake-selected report after binding. For a delegate require its real B author/Turn/Attempt, immutable material subset, and no owner Attempt on the delegate. Do not infer identity or authority from a notification, a historical getter, or a model's output.
3. With C holding the exact token/profile registry lock, allow only the existing role-fence owner's memory-only one-shot admission callback. A successful commit with a live context is required for invocation. C independently pins private CWD, config inode/issued digest and bridge bytes and checks them immediately around admission. A refusal, uncertain commit, or untrusted receipt is not proof of settlement; do not rerun, release unknown resources, or publish a reply from it. Revoke/drain the capability before removing a managed config.

`TestInvestigationTaskWorkOwnerTransportV30Followup` and `TestInvestigationTaskWorkOwnerTransportV30Report` exercise scope, exact input/report text, key-preserving ACK, B submission and text-gate denial through the real member-tool handlers with SQLite. `TestInvestigationTaskWorkLaunchSQLite*` exercises typed launch admission and settlement through the scheduler with a synthetic executor. `TestBoundWorkDelegationTransport` covers the exact Artifact subset with the full HTTP handler stack. `TestUnsupportedV30TaskWorkDoesNotStopScheduler` exercises the real queue for all three kinds without a typed launcher. The `TestFreshTaskWorkB29NativeWire*` fixtures cover the plain-text path: a wrong resource refuses native execution; a lost write result or a terminal with an incomplete receipt retains the claim and publishes nothing. These fixtures do not run a real Pi/Codex model or qualify v31/A7.
