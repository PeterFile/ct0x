# 群组后台讨论：本机预览

默认关闭。只有 SQLite 已安装后台调度迁移、且本机操作者显式提供授权文件和受支持的 Pi 路径时，才可通过普通 `workspace` 启动入口选择此预览：

```sh
workspace --enable-execution --pi-path /trusted/bin/pi \
  --group-background-dispatch-preview /trusted/a1-approval.json
```

授权文件必须是本机可信的 0600 或 0400 普通文件（非符号链接，最多 16 KiB）。文件、Pi 路径及其上级目录必须由操作者控制，包括实际的 CLI 配置；不得放进已授予 Agent 写入权限的目录。用原子替换更新文件。不要写入凭据、个人认证配置、聊天内容或模型输出。

授权文件至少提供 `preset` 或 `create` 之一，也可以同时提供。两种模板都填写非空的 `id`、`name`、`role`，并使用文件顶层批准的 Pi 提供方和精确模型。原有 `preset` 配置继续有效。只有显式提供 `create` 才授权兜底创建。

调度先复用本群符合已批准配置且无外部工作区的活跃成员。没有合适成员且未满员时，先尝试获批且可用的 `preset`，再使用显式获批的 `create`。增员授权来自本机配置。全局执行并发仍由 `--execution-max-active` 决定。

| 字段 | 说明 |
| --- | --- |
| `provider_id`, `model` | `/api/v1/providers` 中所选 `--pi-path` 的提供方 ID、无歧义的精确 Pi 模型选择器。 |
| `max_active_members`, `approval_expires_at` | 每群活跃成员上限（1–200）、批准截止时间（RFC 3339）。 |
| `preset`, `create` | 分别授权预设入群和兜底创建。每个已提供的模板都是包含三项必填字段的 JSON 对象。 |
| `paused` | 可选，设为 `true` 暂停后台调度。 |
| `qualification` | 当前预览的可信就绪声明。可省略，调度等待有效声明。字段为 `provider_id`、`model`、`path`（与目录中的选定路径相同）、`version`、`transport`（`pi_one_shot`）及 `observed_at`（实际观测时间，RFC 3339）。声明与批准和实际适配器匹配。当前预览按 `observed_at` 使用过去 30 秒内的观测。 |

调度需要有效的无工具资格证据，绑定实际 Pi 启动方式、原 CLI 账号和端点以及精确模型。当前预览接收可信操作者根据实际成功的无工具全新 Pi 单轮提供的声明。版本、登录和适配器检查仅用于诊断。启动环境或账号配置变化时，操作者应撤回原声明。生产自动就绪仍缺能核验当前 Pi 账号和端点的绑定证据，预览默认关闭。

每个既有调度周期在认领前重新读取授权文件，只使用当次有效的模板。文件撤回、暂停、授权或证据到期、绑定不匹配、Pi 不可用或配置无效时，一旦采样即移除就绪。已认领执行继续沿用原终态和资源释放规则。

预览启动后，进程内的保守墙钟随单调经过时间推进，只向前校准；文件缺失、替换或暂停均不重置它。`observed_at` 仍不得晚于原始墙钟。授权和证据的截止时刻均不包含在有效期内；发布给 Store 的截止不晚于原始绝对截止，也不晚于采样时的原始墙钟加上保守钟算出的剩余时间。原始墙钟追上前，新证据也可能提前过期或被拒绝。

此保护不跨重启，也不能验证操作者填写的时间戳。时钟回拨时应先撤回旧声明，校准后用实际新观测重新出具。未被采样的瞬时跳变，以及平台休眠时未计入单调钟的时间，不在保护范围。若恰在命令层采样与 Store 建立快照之间回拨，Store 用自己的墙钟样本计算单调期限，该快照可能比命令层估算存活更久，但仍受发布的墙钟截止及 Store 本地有效期上限约束；下个调度周期会重新核验。

缺少合格证据时，新绑定群的省略收件人消息仍保存并等待，不走旧默认路由。省略启动参数可在重启时停用；之前绑定的群仍保存这类请求，明确指定收件人的普通投递继续走原执行路径。旧群不回填绑定，仅公开消息不唤醒模型。
