# 普通 Pi 成员公开运行说明

`--enable-run-explanation` 默认关闭。须同时使用 `--enable-execution`、`--enable-member-tools` 和 `--pi-member-tools-extension`。仅当普通成员的全新文本轮次使用 Pi 1.4.0、扩展及相邻 `bridge.mjs` 精确匹配本版本、且存储确认支持时，才签发 `publish_run_explanation`。没有 F 表的 v30 库继续执行原工具配置；此选项不安装迁移，也不影响 Codex、原生会话续接、chat intake 或协调/任务角色。

模型只提供 `{ "text": "…" }`：一条专门写给用户看的、不全为空白的 UTF-8 说明，最多 1024 字节，不含 NUL。不要提交私密信息、内部推理或原始日志。运行身份取自服务端已接受且仍有效的认领；桥接器从工具名、签发的运行 ID 和原生调用 ID 派生幂等键。不发送聊天消息，也不创建唤醒投递。

公开说明以 `GET /api/v1/me/agent-runs/{run}?group_id={group}` 的 `public_explanation` 项为准。它不是运行回执或操作证明。

发送前，桥接器在服务端绑定的私有运行目录中独占创建 `run-explanation-bridge-attempt`（0600，原幂等键、一个换行、逐字节原文），同步文件及目录后才发送。此记录不含 bearer 或认领令牌，也不依赖 stdout 或请求到达服务端。服务端的 `run-explanation-attempt.json` 仍是独立的事务前记录。旧扩展对原有配置保持兼容，但不签发新的说明发布权限。

仅在子进程、事件交付及服务端处理全部收尾，且当前调用的起止事件、ACK、两份记录和运行结果一致时，才清理可能已发送的记录。可确定未发送或被拒绝的首次请求可以仅清理自己的记录。中断、缺失或不匹配的确认保持未知并保留执行资源，即使模型报告成功。桥接器不会自动重发；未确认的记录仅用于对账，不提供重放权限。
